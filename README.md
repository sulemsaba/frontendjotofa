# JOTOFA Group — Public Frontend

This repository contains the public-facing Next.js website for **JOTOFA GROUP**, a diversified holding company operating across Tanzania and East Africa through five subsidiaries: ICT (UTEC), logistics (courier), cleaning, security, and staffing. The site marketes the group, lists open positions under Careers, publishes company news and CSR stories, captures contact submissions and job applications, and serves an RSS feed and sitemap for search engines. It is intentionally a **frontend-only** repo: all dynamic data (jobs, news, applications, contacts) comes from the shared FastAPI backend, which lives in its own repository.

The project is part of a three-repo architecture:

1. **`jotoo-frontend`** — this repo. Public marketing site (Next.js 16 + React 19 + Tailwind v4 + shadcn/ui).
2. **`jotoo-admin`** — internal admin panel (separate repo, separate deployment).
3. **`jotoo-backend`** — shared FastAPI + SQLAlchemy + Alembic backend that both frontend and admin talk to.

Splitting the three concerns into their own repos keeps CI/CD pipelines small, lets each team own a deployable artifact, and prevents unrelated changes (e.g. an admin-only UI tweak) from forcing a rebuild of the public site. This frontend repo therefore contains zero backend code, zero Prisma schemas, and zero admin routes — if you need any of those, look in the corresponding sibling repo.

## Tech Stack

- **Next.js 16** (App Router, `output: "standalone"` for production)
- **React 19** with **TypeScript 5** in `strict` mode
- **Tailwind CSS v4** (via `@tailwindcss/postcss`) with `tw-animate-css` for animations
- **shadcn/ui** component library (Radix UI primitives, CVA, Tailwind merge) configured via `components.json`
- **Framer Motion** for scroll-reveal and page transitions
- **next-themes** for dark/light theme switching (defaults to dark)
- **Sonner** for toast notifications, hooked into a custom `use-toast` hook
- **lucide-react** for icons, **react-markdown** for news article rendering
- **Bun** as the package manager (lockfile is `bun.lock`)

All UI primitives live under `src/components/ui/` and are generated by `shadcn/ui` — feel free to add or remove them via `npx shadcn@latest add <component>`. The site-level components (navbar, hero, footer, news-section, contact form, job apply modal, etc.) live directly under `src/components/` and `src/components/pages/`.

## Getting Started

### Prerequisites

- **Node.js 20+** (recommended 22+)
- **Bun** (install from <https://bun.sh>) — used as both package manager and runtime
- A running **backend** (the `jotoo-backend` repo) reachable at the URL you set in `NEXT_PUBLIC_API_BASE_URL`. The frontend will still start without it, but Careers, News, and Contact will show empty states.

### Install & Run

```bash
# 1. Install dependencies
bun install

# 2. Copy env vars and adjust if your backend runs elsewhere
cp .env.example .env.local

# 3. Start dev server
bun dev
# → http://localhost:3005
```

### Build for Production

```bash
bun run build
bun run start
```

The default `next.config.ts` uses `output: "standalone"`, which produces a self-contained `.next/standalone/` directory suitable for Docker / VM deployments. If you deploy to Vercel, you can drop the `output: "standalone"` line — Vercel handles output tracing itself.

## Environment Variables

All variables are loaded at build/runtime by Next.js. Client-exposed variables MUST be prefixed with `NEXT_PUBLIC_`.

| Variable                     | Required | Default                          | Description                                                       |
| ---------------------------- | -------- | -------------------------------- | ----------------------------------------------------------------- |
| `NEXT_PUBLIC_API_BASE_URL`   | yes      | `http://localhost:8000/api`      | Base URL of the FastAPI backend.                                  |
| `NEXT_PUBLIC_SITE_URL`       | no       | `http://localhost:3005`          | Canonical site URL, used by sitemap, RSS feed, and JSON-LD.       |
| `NEXT_PUBLIC_WHATSAPP_NUMBER`| no       | —                                | E.164 phone number for the floating WhatsApp button, if enabled.  |

Copy `.env.example` to `.env.local` and adjust values for your environment. Never commit `.env.local`.

## Backend Contract

The frontend talks to the backend exclusively through `src/lib/api.ts`, which exposes four typed functions:

- `getJobs()` → `GET /public/jobs?page_size=100`
- `getSubsidiaries()` → `GET /public/subsidiaries`
- `submitApplication(formData)` → `POST /public/applications` (multipart form, resume + cover letter)
- `submitContact(payload)` → `POST /public/contacts`

The contact form also has a Next.js route handler at `src/app/api/contact/route.ts` that proxies to the same backend endpoint — this is kept so the form can submit without exposing the backend URL in the browser network tab if desired. If you change any endpoint shape on the backend, update `src/lib/api.ts` (and the contact route) in this repo to match.

## Deployment Notes

- **Standalone output**: `next.config.ts` sets `output: "standalone"`. After `bun run build`, copy `.next/standalone`, `.next/static`, and `public/` to your server and run `node .next/standalone/server.js` (or `bun .next/standalone/server.js`).
- **Caddy / reverse proxy**: if you were previously using the `Caddyfile` and `start-all.sh` from the old monorepo, those now belong in your deployment repo / host config, not here.
- **Allowed dev origins**: `next.config.ts` allows `.space-z.ai` for dev previews. Add your own preview domain pattern there if needed.
- **TypeScript**: Type checking is enforced in `next.config.ts`. Fix type errors rather than suppressing them.

## Repository History

This repo was extracted from a single monolithic `jotoo` repository that bundled the public frontend, the admin panel, and the FastAPI backend together with build artifacts, screenshots, and Python cache files. It has been split into three independent repos for cleaner ownership and deployment. The initial commit in this repo contains only the public Next.js site, with all admin code, backend code, Prisma schemas, build artifacts, and design-review screenshots removed. There is no inherited git history — the original monorepo remains available for reference at its original location.
